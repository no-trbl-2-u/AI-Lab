Springdrift

Seamus Brady · April 2026 · arXiv:2604.04660
An auditable persistent runtime for LLM agents

Most agent work asks how do I configure this loop well? This paper asks a different question: what should an agent's execution environment guarantee in the first place?

01The problem it exists to solve

An agent you work with for weeks is a different thing from one you use for ten minutes. Not because it needs to be smarter — because you need to be able to check what it did.

Session-bounded agent

  • Context discarded or compressed at the end
  • No way to reconstruct why it decided something
  • Conduct varies session to session
  • Failures vanish silently

Persistent runtime

  • State derived by replaying an append-only log
  • Every decision traceable to the cycle that made it
  • Commitments persist across contexts
  • Crashes absorbed by supervision, and recorded
Adding memory to a session-bounded system does not solve this — it adds recall without accountability, persistence without auditability.

That is the whole argument in one line. Memory is not the same as accountability, and most systems that added the first assumed they got the second.

02How it works

Every input runs the same cycle. Two safety gates bracket the model, and nothing reaches the model without the agent's own state being attached first.

The idea most worth stealing

The sensorium. A small block of the agent's own state — clock, queue, recent success rate, which sub-agents are healthy — pasted into every prompt. No tool call. The agent doesn't have to decide to look.

Why that matters: diagnostics behind a tool call are diagnostics the agent won't run — it has to decide checking is worthwhile before it has the information that would tell it. Making self-state ambient removes the decision.

03How much to believe it

This is the part to read before the results. The paper is a single deployment by a single author over 23 days — and it says so, repeatedly and without defensiveness. Different claims carry very different weight:

Rule-system properties
Measured · formal
All 7,056 rule pairs checked. Zero contradictions. But this proves the rules are consistent, not that they make anything safe.
Retrieval benchmark
Measured · synthetic
800 generated cases, not real ones. The author flags that the scoring rule tilts toward his own method.
Operational scale
Descriptive
Real counts from a real deployment — but counts, not comparisons. Nothing was measured against an alternative.
Everything the agent did
Anecdotal · n=1
Five stories, hand-picked as illustrations rather than sampled. Compelling, but not evidence the design generally works.
Read this as a worked design, not as proof. The author's own closing line: "We present design arguments rather than proven results throughout." Take the ideas; measure them yourself.

The interesting bit isn't the win — it's why the method exists. Ordinary retrieval treats a memory that led to ten failures exactly like one that led to ten successes. Here, cases record their outcome, and things that worked get retrieved more.

05The one thing to remember

On 21 March the agent found a security hole in itself. A tool meant for asking the human a question was available to its own sub-agents — and it fed their text back into the main loop as if the human had typed it.

The injection was invisible to my telemetry because responses routed back through the main loop as normal user inputs.

Worth checking in any setup where a sub-agent's output can reach a human. If a delegated agent's text can arrive on the same channel as yours, it can claim your authority — and the logs won't show it.

06What we take from it

Take these

  • Memory that fades. Facts lose confidence on a 30-day half-life, so stale notes stop mattering without any cleanup job ever running.
  • Promote what worked. Rank memories by outcome, not by how often they were read.
  • Name the rule that fired. Don't say "check failed" — say which rule, in order.
  • Fence the operator channel. See section 05.

Leave these

  • The runtime itself. 62,000 lines of Gleam on Erlang. No incremental adoption path — it's all or nothing.
  • The ethics engine. Genuinely interesting, explicitly experimental, and removable without touching anything else.
