# Phase 02 — session schema and verdict enforcement

```yaml
phase: 2
claim: >
  Every brainstorm resolves to exactly one verdict, and a session claiming it
  produced a gap names a gap that actually exists.
cites: GAPS.md#g12
build: brainstorms/ + the Session schema in guards/gaps.mjs + session fixtures
failing_check: node guards/gaps.mjs --fixtures
done_when: >
  Six session fixtures behave as specified — one passes, five fail for one named
  reason each.
type: build
```

## The failure this exists to prevent

[G12](../../../GAPS.md) is *ideas don't become gaps; they become code or they
evaporate.* A `/brainstorm` that ended in a nice conversation and no artifact
would be the third way to fail: it neither built the thing nor recorded the
decision, so the idea gets re-had in three weeks.

The schema makes that impossible by construction.

## Schema

```yaml
type: Brainstorm Session
title: <the idea, one line>
description: <the design problem underneath>
date: YYYY-MM-DD
verdict: gap | declined | resource-question | deferred
gap: G15                     # required iff verdict is `gap`, and must resolve
provenance: observed         # required iff verdict is `gap`
reason: <…>                  # required iff verdict is `declined`
cites: [9, 12]               # notes consulted, by id; each must exist
generated: { by: brainstorm/0.1, at: <ISO-8601> }
```

The conditional requirements are the point:

| Defect | Why it matters |
|---|---|
| `verdict: gap` with no `gap:` | The session claims to have fed the spine and didn't |
| `verdict: gap` with no `provenance:` | An untagged gap can't be ranked, and ranking is what `ROADMAP.md` does |
| `verdict: declined` with no `reason:` | An unrecorded rejection gets re-litigated — the same logic as `REJECTED.md` |
| `gap:` naming an ID absent from `GAPS.md` | The link is decorative |

## Why no separate index for declined ideas

`grep -l 'verdict: declined' brainstorms/*.md`. Same move as the OKF frontmatter
on `resources/` — the state is queryable where it lives, and a second index file
would be one more thing to drift out of sync.

This satisfies G12's closure condition that *one idea has been explicitly
declined rather than built, with the reason recorded.*

## Note

`deferred` requires a trigger condition **in the body**, not in frontmatter —
that one genuinely needs prose, and a guard checking for its presence would be
checking that a heading exists rather than that a condition was named. The skill
carries the rule instead: *`deferred` without a trigger is a maybe in a costume.*
