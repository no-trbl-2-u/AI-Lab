# Phase 01 — the queue format and its guard

```yaml
phase: 1
claim: >
  A candidate resource can be recorded with a machine-checkable link to the
  specific weak point it targets, and a guard rejects one that isn't.
cites: lab/reinforce/PRD.md#the-queue
build: resources/queue/ + guards/reinforce.mjs + fixtures
failing_check: node guards/reinforce.mjs --fixtures
done_when: >
  The guard passes a valid queue entry and fails each invalid fixture for one
  named reason.
type: build
```

## Why this is first

No searching happens here. The queue format is the cheap half and the search is
the expensive half — if the format is wrong, that's a fixture edit; if it's
wrong *after* a real run, it's a re-run. Building the container before the
contents is also the only way phase 02 has something to be checked by.

## What gets built

`resources/queue/<slug>.md`, OKF-conformant, per the schema in
[PRD.md § The queue](../PRD.md). The field that does the work is `targets`:

```yaml
targets: 09#evidence     # a note's weak point — field must be one of the eight
targets: G6              # a gap ID
```

Both must resolve or the guard fails. **This is the field that separates a
candidate from a bookmark.**

## The guard

`guards/reinforce.mjs` checks, for every file in `resources/queue/`:

1. Frontmatter parses, and `type` is non-empty (OKF conformance).
2. `targets` is present and resolves — the note exists and the field is one of
   the eight points, or the gap ID is in `GAPS.md`.
3. `axis` is one of `measured` · `alternative` · `opposing` · `falsifier` · `gap`.
4. `stale_after` is present and parseable.
5. `resource` is **not** already a note in `resources/` or a line in
   `REJECTED.md`.
6. `generated.by` is present.
7. The body has a `## Why this is a candidate` section and a
   `## What would disqualify it` line.

Check 5 does double duty: it prevents re-litigating a rejection *and* enforces
dequeue-on-intake, since a candidate that became a note now collides with
itself.

## Notes

Reuse `guards/okf.mjs`'s frontmatter split and actor regex rather than
re-deriving them. A second, subtly different YAML parser in the same repo is a
drift source.

Staleness here is a **failure**, not a report — unlike the pool. A queue entry
past `stale_after` is the graveyard failure mode arriving, and the fix is
cheap: intake it or sweep it to `REJECTED.md` with `expired in queue`.
